## 1. 两层设计:为什么训练器分两层?

```
BaseTrainer (engine/trainer.py, 通用主循环)
  ├── 什么时候取数据、什么时候算损失、什么时候反向传播、什么时候存权重
  ├── 回调系统(你的进度条就挂在 on_fit_epoch_end 上)
  └── 但它"不知道"检测任务长什么样
DetectionTrainer (models/yolo/detect/train.py, 检测专用)
  ├── 数据怎么加载(build_dataset / get_dataloader)
  ├── 模型怎么搭(get_model → DetectionModel)
  ├── 损失叫什么名字(box_loss, cls_loss, dfl_loss)
  └── 同样的框架还有 SegmentTrainer / PoseTrainer / ClassifyTrainer...
```

这就是**模板方法模式**:父类定流程骨架,子类填任务细节。
读 `detect/train.py`(232 行)可以看到一个训练器要回答的全部问题。

## 2. `_do_train()` 主循环(简化版,保留真实结构)

```python
for epoch in range(self.start_epoch, self.epochs):
    self.model.train()                        # 切训练模式(启用 dropout/BN 更新)
    pbar = tqdm(enumerate(self.train_loader)) # 进度条
    for i, batch in pbar:
        self.run_callback("on_train_batch_start")
        # ① 预处理:搬到设备 + 归一化到 0~1(detect/train.py:107)
        batch = self.preprocess_batch(batch)
        # ② 前向:模型输出原始预测
        preds = self.model(batch["img"])
        # ③ 算损失:v8DetectionLoss(preds, batch) → 标量
        self.loss, self.loss_items = self.model.loss(batch, preds)
        # ④ 反向传播三步曲(PyTorch 标准写法)
        self.scaler.scale(self.loss).backward()   # 放大梯度防下溢(AMP)
        self.scaler.step(self.optimizer)          # 更新权重
        self.scaler.update()
        self.optimizer.zero_grad()
        self.memory_format... / pbar 更新
    # ---- 每个 epoch 结束 ----
    self.run_callback("on_fit_epoch_end")     # ★ 我们的进度回调
    # 验证:在 val 集上算 mAP
    self.metrics, self.fitness = self.validate()
    # 保存:best.pt(历史最优) / last.pt(最新)
    self.save_model()
```

**app.py 的对应关系**:`run_training()` 里的 `on_epoch` 回调就是被 `run_callback("on_fit_epoch_end")` 调用的,它从 `trainer.epoch / trainer.metrics` 里读数写进 `train_state`,平板轮询显示 —— 现在你可以从源码层面解释自己的进度条了。

## 3. 迁移学习:为什么几十张图就够

`YOLO("yolo11n.pt").train(...)` 时发生的事:

```
1. _load("yolo11n.pt")     读预训练权重:Backbone 已认识边缘/纹理/部件
2. get_model(cfg, weights) 重建网络;类别数 nc 换成你的(如 2 类)
    → 检测头的最后一层(分类层)维度变了,该层权重随机初始化
    → Backbone + Neck 的权重原样保留 ← 迁移学习的全部秘密
3. 训练时所有层一起微调(默认不冻结)
```

所以:预训练给了"会看图"的眼睛,你只教它"认你的东西"。从零训练 COCO 级别需要 118k 张图和数百 GPU 时;微调只需几十张图和一台笔记本。

**动手实验**:`model.train(..., freeze=10)` 冻结前 10 层再训,对比 mAP 和速度 —— 有时小数据集冻结 Backbone 反而更好(防过拟合)。

## 4. 数据管线(简述)

```
data.yaml → 检查/生成 .cache(第二次训练秒启动的原因)
  → YOLODataset(data/build.py)
      每张图:读图 + 读标注 txt → mosaic/翻转/色域 等增强(train 模式才开)
  → DataLoader 多进程加载(batch=8, workers=0 是为了 Windows 稳定)
```

`detect/train.py:107 preprocess_batch()` 里还有一个值得注意的细节:
`multi_scale` 参数让每个 batch 随机换尺寸训练,提升模型对不同大小物体的适应性。

## 5. 训练产物(models/run/ 目录)

```
run/
├── weights/
│   ├── best.pt    验证集 fitness 最高的那轮 ← 训练完真正要用的
│   └── last.pt    最后一轮(用来断点续训 resume=True)
├── results.csv    每轮的完整指标(用 Excel 打开看 loss 下降曲线)
├── results.png    官方画的曲线图 ← 我们的 /api/train/curve 返回它
├── confusion_matrix.png  混淆矩阵:哪些类别互相认错
├── train_batch0.jpg      训练样本长什么样(含 mosaic 增强效果)
└── val_batch0_labels.jpg vs val_batch0_pred.jpg
                           同一批图:人工标注 vs 模型预测,肉眼对比最直观
```
