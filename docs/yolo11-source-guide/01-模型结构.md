# 01 · YOLO11 模型结构(Backbone → Neck → Head)

> 对应源码:`UL/nn/modules/conv.py` `block.py` `head.py` 和 `UL/nn/tasks.py`

## 1. 三段式结构:所有 YOLO 都长这样

```
输入图片 (1×3×640×640)
    │
    ▼
┌─────────────┐   逐级下采样(步幅 2,4,8,16,32)
│  Backbone   │   提取特征:越深越小但越"懂语义"
│  主干网络    │   输出 3 个尺度的特征图:
└──────┬──────┘     P3: 80×80  (小物体)   P4: 40×40 (中物体)   P5: 20×20 (大物体)
       ▼
┌─────────────┐   把深层(语义强)和浅层(位置准)的特征融合
│    Neck     │   YOLO11 用 PAN-FSPN 结构,全是卷积拼接
│  特征融合    │
└──────┬──────┘
       ▼
┌─────────────┐   对每个尺度输出预测:每个格子预测若干个框
│    Head     │   YOLO11 的 Detect 头是"解耦"的:
│  检测头      │   分类分支 + 回归分支分开算
└─────────────┘
```

**直观理解**:80×80 的特征图上每个格子对应原图 8×8 像素区域 → 负责小物体;
20×20 的格子对应 32×32 像素 → 负责大物体。这就是"三个尺度"存在的原因。

## 2. 积木块详解(都在 `UL/nn/modules/`)

### Conv —— 最基础单元(`conv.py:39`)

```python
class Conv(nn.Module):
    # 标准卷积块:Conv2d + BatchNorm + SiLU 激活,三件套打包
    # 几乎所有更复杂的块都由它组合而成
```

### C3k2 —— 主干特征块(`block.py:1069`,继承自 C2f)

```python
class C3k2(C2f):
    # YOLO11 相对 YOLO8 的主要改动之一
    # 结构:输入先 1×1 卷积分成两半,一半过若干个 C3k 小块,再拼接融合
    # 作用:在少算力的前提下加深网络、增强特征表达
    # "C3k" = 用 3×3 卷积的瓶颈块;"2" = 两段式设计
```

### SPPF —— 空间金字塔池化(`block.py:208`)

```python
class SPPF(nn.Module):
    # 连续做 5 次 5×5 最大池化再拼接
    # 作用:让同一层特征同时"看到"不同大小的感受野
    # 位置:Backbone 最末端,给 Neck 提供多尺度上下文
```

### DFL —— 分布式焦点回归(`block.py:58`)

```python
class DFL(nn.Module):
    # YOLO 独创:不直接回归框坐标,而是把每条边长预测成一个"分布"
    # (16 个 bin 的概率),再用 softmax 期望值得到最终坐标
    # 好处:框的边界可以"不确定",训练更稳定
    # 详见 04-损失函数.md
```

### Detect —— 检测头(`head.py:26`)

```python
class Detect(nn.Module):
    # 解耦头 + Anchor-Free 设计:
    #   对 P3/P4/P5 每个尺度的每个格子,并行两个分支:
    #     cv2 分支 → 回归:到框四条边的距离(经 DFL 变换)
    #     cv3 分支 → 分类:每个类别的置信度
    # 推理时 forward() 还会把输出整合成 (1, 84, 8400) 的大表
    #   8400 = 80×80 + 40×40 + 20×20 个格子(每格1个框)
    #   84   = 4 个坐标 + 80 个类别分数
```

### Segment —— 分割头(`head.py`,继承 Detect)

```python
class Segment(Detect):
    # 在 Detect 基础上加第三个分支 cv4:每个格子预测 32 维原型系数,
    # 与一组共享的"原型掩码"(Proto 模块输出)加权组合,
    # 得到每个目标的像素级掩码 → app.py 的测量功能全靠它。
    # 输出变为 (1, 116, 8400):116 = 84 + 32 个掩码系数
    # 训练时也多一项 mask_loss(掩码与标注多边形的重叠损失)
```

## 3. 从 yaml 到 PyTorch 模型:`parse_model`(`UL/nn/tasks.py:1539`)

YOLO 的网络不是手写的,而是用 **yaml 配置文件描述**,再由 `parse_model()` 解释执行:

```yaml
# UL/cfg/models/11/yolo11.yaml(节选)
backbone:
  - [-1, 1, Conv, [64, 3, 2]]      # 第0层:来自上一层,重复1次,Conv块,参数
  - [-1, 1, Conv, [128, 3, 2]]
  - [-1, 2, C3k2, [256, False, 0.25]]
  ...
head:
  - [[-1, 6], 1, Concat, [1]]      # Concat:把第6层和上一层拼接
  - [-1, 2, C3k2, [512]]           # 融合后的特征再加工
  ...
  - [[16], 1, Detect, [nc]]        # 最后一层:检测头,nc=类别数
```

`parse_model()` 做的事(简化):

```python
for 每一行 in yaml的层列表:
    from_, repeats, module, args = 该行四个字段
    m = 积木类字典[module]                # "Conv"→Conv类, "C3k2"→C3k2类...
    计算该层输入通道数 ch = 上一层输出(或 Concat 时多个来源)
    module = m(*args)                     # 实例化
    记录该层输出通道数,供下一层使用
最后把所有层塞进 nn.Sequential → 就是完整模型
```

**关键认知**:`YOLO("yolo11n.pt")` 加载权重时,n/s/m/l/x 五个规模用的是**同一份 yaml**,只是每层的通道数乘上不同的 `width_multiple`(n=0.25,m=1.0...)。所以"换个更大的模型"只是换宽度和深度系数。

print(net)                       # 逐层打印:每层的类型/参数/输出形状
