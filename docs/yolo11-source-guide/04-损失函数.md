## 1. 总览:损失 = 三项加权和

```python
# detect/train.py:170 定义的三个名字,就对应这三项
self.loss_names = "box_loss", "cls_loss", "dfl_loss"

loss = λ_box · box_loss + λ_cls · cls_loss + λ_dfl · dfl_loss
# 默认权重 λ 在 cfg/default.yaml: box=7.5, cls=0.5, dfl=1.5
# 直觉:定位重要(权重最大),分类其次,分布回归再次
```

## 2. 前置难题:8400 个预测框,谁是"对的"?

模型每张图输出 8400 个框,但标注里可能只有 3 个物体。**必须先决定"哪个预测框对哪个真实框负责",才能算损失** —— 这个步骤叫**正负样本分配**,是检测训练的灵魂。

老方法(YOLOv5 及更早):anchor 框和哪个真实框 IoU 最大就归谁。
YOLOv8+ 用更聪明的 **TaskAlignedAssigner**(`utils/tal.py`):

```python
# 对每个真实框,给所有 8400 个候选打分:
alignment = cls_score^α × IoU^β      # 分类和定位"都对得上"才算好
# 选 topk=10 个得分最高的候选 → 标为正样本
# 其余全部标为负样本(它们只参与分类损失,目标为"什么都不是")
```

直觉:不搞"一刀切"的几何规则,而是**让"已经预测得又准又确信"的格子继续负责这个物体** —— 训练信号集中在最有希望的预测上。

## 3. 三项损失逐个拆解

### 3.1 cls_loss —— 分类损失(二元交叉熵)

```python
# loss.py: v8DetectionLoss.__call__ 内
# 每个预测框 × 每个类别 各算一次 BCE:
#   正样本:其负责类别应为 1
#   负样本:所有类别应为 0
# 用 BCE 而非 softmax:允许一个格子"同时是猫和宠物"的多标签语义
```

### 3.2 box_loss —— 定位损失(CIoU,`loss.py:109 BboxLoss`)

```python
# 正样本才有框回归损失
iou = CIoU(pred_box, target_box)
# CIoU = IoU 重叠度 − 中心点距离惩罚 − 长宽比惩罚
# 相比裸 IoU:即使两框不相交(IoU=0)也有梯度信号,能"拉着"框往目标挪
box_loss = (1 − iou).mean()
```

### 3.3 dfl_loss —— 分布式焦点损失(`loss.py` + `block.py:58 DFL`)

YOLO 独创,最难也最有意思的一项:

```python
# 传统回归:直接预测左/上/右/下四条边的距离(一个数)
# DFL 回归:把每条边预测成 16 个 bin 上的概率分布,再取期望
#   边长 = Σ (概率_i × i)     i = 0..15(reg_max=16)
#
# 为什么更好?
#   当物体边界模糊(被遮挡/过曝)时,分布会自然变"宽"表达不确定
#   训练时用类似 Focal Loss 的加权,让分布的形状逼近 one-hot(目标边长)
```

## 4. `v8DetectionLoss.__call__` 代码骨架(`loss.py:456`)

```python
def __call__(self, preds, batch):
    # ① 拆出三个尺度的预测,展平成 (8400, ...) 并转成 xyxy 框
    # ② 标注信息搬到同一设备
    # ③ 正负样本分配(第 2 节讲的 TAL)
    assign_result = self.assigner(pred_scores, pred_boxes, 目标)
    # ④ 分别算三项损失(都只对正样本算框损失,全样本算分类损失)
    loss[0] = self.bbox_loss(...)   # 内部含 CIoU + DFL
    loss[1] = self.cls_loss(...)
    # ⑤ 乘权重、除以正样本数归一,返回 (总损失, 三项明细)
    return loss.sum() * batch_size, loss.detach()
```

## 5. 看懂 results.csv 里的曲线

训练页曲线图的各列含义(对照本章):

| 曲线 | 正常走势 | 不正常说明 |
|---|---|---|
| train/box_loss | 持续下降 | 不降 → 学习率太小或数据标注有错 |
| train/cls_loss | 持续下降 | 先降后升 → 过拟合,数据太少 |
| train/dfl_loss | 缓慢下降 | 本来就难降,不用焦虑 |
| metrics/mAP50 | 持续上升 → 平台 | 上升又下降=过拟合,取 best.pt 没问题 |
| val/box_loss | 下降 | 上升 → 过拟合的信号 |
