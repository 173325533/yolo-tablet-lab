> 对应源码:`UL/engine/model.py:478 predict()` → `UL/engine/predictor.py` → `UL/engine/results.py`

## 1. 全流程图(以 app.py 里的调用为例)

```python
results = model.predict(frame, imgsz=640, conf=0.4)
```

```
原始图片 (480, 640, 3) BGR
   │ ① 预处理  LetterBox:按比例缩放到 640×640,不足处填灰边
   │            (保持长宽比,不变形 —— 这就是为什么检测框坐标要"还原")
   ▼
输入张量 (1, 3, 640, 640),0~1 归一化
   │ ② 前向    AutoBackend.forward() → DetectionModel
   │            支持 PyTorch/ONNX/TensorRT 等多种后端,接口统一
   ▼
原始输出 (1, 84, 8400)
   │            84 = 4 坐标 + 80 类别分数
   │            8400 = 三个尺度所有格子的预测框
   │ ③ NMS     non_max_suppression()  [UL/utils/nms.py]
   │            a. 先按 conf=0.4 过滤掉低置信度的几千个框
   │            b. 按类别分组,组内按置信度排序
   │            c. 保留最高的框,删掉与它 IoU>0.7 的重叠框(同一物体的重复检测)
   ▼
最终框列表 [n, 6]:x1,y1,x2,y2, conf, cls
   │ ④ 还原    把坐标从 640×640 letterbox 空间映射回原图尺寸
   ▼
Results 对象 → results[0].plot() 画出框
```

## 3. Results 对象:你真正打交道的产物

`app.py` 的 `draw_detections()` 里用过它,现在看懂每个字段:

```python
r = results[0]                # 单图预测也有批次维度,取第一个
r.boxes                       # Boxes 对象,以下都是它的属性
r.boxes.xyxy     # (n,4) tensor,每个框的左上右下角像素坐标
r.boxes.conf     # (n,)  tensor,置信度,如 0.945
r.boxes.cls      # (n,)  tensor,类别编号,如 5.0
r.boxes.xywh     # (n,4) 中心点+宽高格式
r.names          # dict {5: "bus", 0: "person"} ← model.names 就是这个
r.orig_img       # 原图(numpy),plot() 就是在它上面画框
r.plot()         # 返回画好框的 numpy 图
r.speed          # {'preprocess': 2.1, 'inference': 280.5, 'postprocess': 1.8} 毫秒
```

**动手实验**:`print(r.speed)` —— 你会看到 CPU 推理里 95% 的时间都花在 `inference`(网络前向),预处理后处理几乎免费。这就是为什么压缩输入图片能明显加速。

## 4. conf 与 IoU:两个最重要的推理参数

```python
model.predict(frame, conf=0.4, iou=0.7)
```

- **conf(置信度阈值)**:低于它的预测直接丢弃。调低 → 漏检少但误报多
- **iou(NMS 重叠阈值)**:两个框重叠度超过它的会被当作"同一物体的重复"删掉。调低 → 保留的框更少更"干净";调太低 → 靠得近的两个物体会被误删一个
- **动手实验**:同一张图分别用 `conf=0.1, 0.4, 0.9` 检测,对比 `len(r.boxes)`

## 5. 流式推理(app.py 的摄像头流就在用)

```python
results = model.predict(source=0, stream=True)   # source=0 表示摄像头
for r in results:                                 # 生成器:处理一帧返回一帧
    处理(r)                                      # 不用等所有帧一起算,省内存
```

`stream=True` 返回生成器而不是列表,`predictor.py` 的 `stream_inference()` 由此得名 —— 我们的 `/video` 接口能持续出画面靠的就是它。
